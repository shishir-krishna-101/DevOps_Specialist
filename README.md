# Python Dictionary & DSA Dictionary for DevOps

A structured, DevOps-first learning roadmap for Python and Data Structures & Algorithms (DSA). Learn the topics most useful for DevOps engineering first, then continue into broader Python and DSA topics when you need deeper coverage.

## Learning paths

```text
Python Dictionary
├── Python for DevOps
│   └── Core Python topics and practical scripting skills useful to DevOps engineers
└── Complete Python
    └── The broader Python curriculum that continues beyond the DevOps-focused path

DSA Dictionary
├── DSA for DevOps
│   └── A focused set of data structures, algorithms, and problem-solving patterns
│       useful for automation, troubleshooting, and technical interviews
└── Complete DSA
    └── The broader DSA curriculum that continues beyond the DevOps-focused path
```

## Recommended order

1. Start with **Python for DevOps** if your immediate goal is automation and operational scripting.
2. Continue with **Complete Python** for language features and topics beyond the DevOps-focused path.
3. Study **DSA for DevOps** for a practical introduction to data structures, complexity, and common algorithmic patterns.
4. Continue with **Complete DSA** for broader and more advanced DSA coverage.

You can study the Python and DSA paths independently. Python fundamentals that are needed by the DevOps path should be taught there first; the Complete Python path should extend that foundation rather than repeat it. Likewise, DSA for DevOps should introduce only the DSA concepts it needs, while Complete DSA provides the deeper continuation.

## Content principles

- **DevOps-first:** prioritize topics that help with scripting, automation, APIs, files, processes, testing, and operational problem-solving.
- **Progressive learning:** deeper or less immediately relevant material belongs in the continuation paths.
- **One canonical explanation:** link to an existing explanation or implementation instead of copying the same material into multiple tracks.
- **Practice and verification:** examples should be understandable, runnable where appropriate, and accompanied by meaningful tests or expected behavior when verified.
- **Source transparency:** technical references and external learning resources will be listed in `resources/SOURCES.md`. External code will not be copied without checking its license and attribution requirements.

## Source and accuracy policy

Official documentation and maintained project repositories take priority for product-specific behavior, APIs, commands, and configuration. Learning roadmaps are repository design choices, not claims that any one curriculum is officially required for DevOps engineers. If a technical detail cannot be verified from authoritative sources, it should be marked as unverified rather than guessed.
