# DevOps Specialist

A structured learning and practice repository for building practical DevOps, SRE, and platform engineering skills. The goal is to bring together tool guides, hands-on projects, interview preparation, and supporting foundations in one navigable place.

> **Repository approach:** learn the concepts, practise with realistic projects, understand the tools, and verify technical details against authoritative documentation.

## What you'll find here

This repository is being built incrementally. Planned learning areas include:

- **DevOps and SRE fundamentals** — Linux, networking, Git, scripting, CI/CD, infrastructure, observability, reliability, and operational practices.
- **DevOps tools** — structured guides and practical examples for relevant tools and platforms, with official documentation used as the source of truth for commands and configuration.
- **Hands-on projects** — portfolio-friendly exercises that connect concepts into reproducible workflows.
- **Interview preparation** — topic reviews, troubleshooting scenarios, practical questions, and relevant problem-solving practice.
- **Python and DSA foundations** — focused learning paths for automation and problem solving, with broader continuation paths for deeper study.
- **References and learning resources** — source mapping and links to authoritative documentation.

These are repository goals and planned areas, not a claim that every section is already complete. Content will be added and reviewed one file at a time.

## How to use this repository

1. Choose the area closest to your current goal.
2. Read the topic guide and follow its exercises in sequence.
3. Use projects to apply concepts in practical scenarios.
4. Verify tool-specific commands, APIs, and configuration against the linked official documentation.
5. Revisit interview and troubleshooting material to test your understanding.

You do not need to complete every learning path before starting a relevant project. Use the prerequisites listed in each section as your guide.

## Quality and source policy

- **Authoritative sources first:** official documentation, project repositories, specifications, and standards take priority for technical behavior.
- **No invented details:** commands, flags, configuration fields, API behavior, and compatibility claims must be verified. Unverified details should be explicitly identified rather than guessed.
- **Learnable, practical content:** guides should explain concepts in a structured way and include examples, exercises, or validation steps where appropriate.
- **Clear separation:** verified facts, repository design decisions, and demonstrations should not be confused with one another.
- **Responsible reuse:** external code and content will not be copied without reviewing licensing and attribution requirements.
- **Incremental development:** files are created, validated, and committed one at a time to keep the repository maintainable.

See [resources/SOURCES.md](resources/SOURCES.md) for the current source map and research policy.
